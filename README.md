# analyze_photos_for_google_business

Ищет дубликаты фото между точками и внутри точки. На входе — папка, в которой лежат папки точек с фото.
На выходе — группы дубликатов в Postgres и страница отчёта с картинками.

Нейросети здесь нет: всё считается по отпечаткам файлов и картинок.

## Установка (один раз)

Нужен Docker.

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
docker compose up -d --wait
```

## Запуск

```
.venv\Scripts\activate
python main.py "C:\путь\к\папке с точками"
```

Папка устроена так: внутри — по папке на точку, в них фото на любой глубине. Название папки точки и есть название точки в отчёте.

| Параметр | Что делает |
|---|---|
| `--subfolder photos` | Брать у каждой точки только подпапку `photos` (или `posts`). Нужен для папки `data` парсера, где фото и картинки постов лежат рядом |
| `--similar 12` | Порог третьего уровня: на сколько из 64 могут отличаться отпечатки у «похожего кадра» |

Пример для папки парсера:

```
python main.py "C:\Dev\retail компания\Google_business_parser\data" --subfolder photos
```

Повторный запуск быстрый: отпечатки считаются только для новых и изменённых файлов. Файлы, которых в папке больше нет, из базы убираются.
В базе хранится один набор — тот, что был в папке при последнем запуске.

## Уровни

Каждая картинка сравнивается с каждой. Найденное делится на три уровня:

| Уровень | Что это | Как определяется |
|---|---|---|
| 1. Точная копия | Файлы совпадают байт в байт | Одинаковый SHA-256 файла |
| 2. Та же картинка, файлы разные | Картинка та же, но сохранена другим файлом. Чаще всего другой размер, но размер может быть и одинаковым (файл пересохранён) | Отпечатки картинок отличаются не больше чем на 4 из 64, а SHA-256 у файлов разный |
| 3. Похожий кадр | Тот же кадр с небольшим отличием: соседний снимок серии, обрезка. Кандидат, смотреть глазами | Отпечатки отличаются на 5–12 из 64 |

Отпечаток картинки (перцептивный хеш) — это 64 бита, которые описывают, как картинка выглядит, а не какие в файле байты.
У одной и той же картинки в разном размере он почти одинаковый.

Пороги подобраны на 763 настоящих фото 17 точек, по просмотру пар глазами: при отличии 0–2 это всегда была та же картинка
в другом размере; при 6–12 — та же сцена с небольшим изменением; с 14 начинаются совсем разные фото, и таких пар сразу много.

Чего эти уровни не ловят: тот же объект, снятый с заметно другого ракурса или с сильным зумом. Для этого нужна модель сравнения
изображений — это следующий этап.

## Что получается

**Страница отчёта** — `report\index.html`, открывается в браузере. На ней:

- четыре цифры сверху и под ними четыре списка с теми же названиями:
  - одинаковые файлы в разных точках (совпадает SHA-256, файл лежит минимум в двух точках);
  - одинаковые файлы внутри одной точки;
  - та же картинка, но файлы разные;
  - похожие кадры — проверить глазами;
- матрица «точка × точка»: сколько общих картинок у каждой пары точек, на диагонали — повторы внутри точки.

Первая цифра равна числу, которое даёт запрос по `sha256` с условием `count(DISTINCT place) > 1`.
В третьем списке показаны все файлы картинки, поэтому одинаковые файлы из первых двух списков могут встретиться там ещё раз.

В списке фото стоят рядом, под каждым — точка, имя файла и размер. Нажатие открывает исходный файл.

**База** — Postgres в Docker, контейнер `photo_analyzer_postgres`, порт 5441, логин и пароль в `.env`:

- `images` — по строке на файл: точка, путь, размер, `sha256`, `phash`, номер группы `group_id` (пусто, если дубликатов нет);
- `duplicate_groups` — по строке на группу: уровень, сколько файлов, в скольких точках.

Все файлы-дубликаты между точками, группами:

```sql
SELECT g.id AS group_no, g.level, i.place, i.name
FROM duplicate_groups g
JOIN images i ON i.group_id = g.id
WHERE g.places > 1
ORDER BY g.level, g.id, i.place;
```

## Что где

| Файл | Что делает |
|---|---|
| `main.py` | Запуск: сканирование, поиск групп, отчёт |
| `analyzer/scan.py` | Обход папки, отпечатки файлов и картинок, превью для отчёта |
| `analyzer/groups.py` | Сравнение всех пар, сборка групп, уровни, матрица точек |
| `analyzer/report.py` | Страница отчёта |
| `analyzer/db.py`, `schema.sql` | Таблицы `images` и `duplicate_groups` |
| `analyzer/config.py` | Настройки и пути |
