# analyze_photos_for_google_business

Ищет дубликаты фото между точками и внутри точки. На входе — папка, в которой лежат папки точек с фото.
На выходе — группы дубликатов в Postgres и страница отчёта с картинками.

Нейросети здесь нет: всё считается по отпечаткам файлов и картинок.

## Установка (один раз)

Нужен Docker.

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
docker compose up -d --wait
```

## Запуск

```
.venv\Scripts\activate
python main.py "C:\путь\к\папке с точками"
```

Папка устроена так: внутри — по папке на точку, в них фото на любой глубине. Название папки точки и есть название точки в отчёте.

| Параметр | Что делает |
|---|---|
| `--subfolder photos` | Брать у каждой точки только подпапку `photos` (или `posts`). Нужен для папки `data` парсера, где фото и картинки постов лежат рядом |
| `--similar 12` | Порог третьего уровня: на сколько из 64 могут отличаться отпечатки у «похожего кадра» |

Пример для папки парсера:

```
python main.py "C:\Dev\retail компания\Google_business_parser\data" --subfolder photos
```

Повторный запуск быстрый: отпечатки считаются только для новых и изменённых файлов. Файлы, которых в папке больше нет, из базы убираются.
В базе хранится один набор — тот, что был в папке при последнем запуске.

## Уровни

Каждая картинка сравнивается с каждой. Найденное делится на три уровня:

| Уровень | Что это | Как определяется |
|---|---|---|
| 1. Точная копия | Файлы совпадают байт в байт | Одинаковый SHA-256 файла |
| 2. Та же картинка, файлы разные | Картинка та же, но сохранена другим файлом. Чаще всего другой размер, но размер может быть и одинаковым (файл пересохранён) | Отпечатки картинок отличаются не больше чем на 4 из 64, а SHA-256 у файлов разный |
| 3. Похожий кадр | Тот же кадр с небольшим отличием: соседний снимок серии, обрезка. Кандидат, смотреть глазами | Отпечатки отличаются на 5–12 из 64 |

Отпечаток картинки (перцептивный хеш) — это 64 бита, которые описывают, как картинка выглядит, а не какие в файле байты.
У одной и той же картинки в разном размере он почти одинаковый. Как он считается — в разделе «Алгоритмы».

Пороги подобраны на 763 настоящих фото 17 точек, по просмотру пар глазами: при отличии 0–2 это всегда была та же картинка
в другом размере; при 6–12 — та же сцена с небольшим изменением; с 14 начинаются совсем разные фото, и таких пар сразу много.

Чего эти уровни не ловят: тот же объект, снятый с заметно другого ракурса или с сильным зумом. Для этого нужна модель сравнения
изображений — это следующий этап.

## Алгоритмы

Используются три вещи: хеш файла, хеш картинки и склейка файлов в группы.

### SHA-256 — хеш файла

Считается из всех байтов файла, получается строка из 64 знаков. Код в `analyzer/scan.py`:

```python
data = path.read_bytes()
sha256 = hashlib.sha256(data).hexdigest()
```

- Байты одинаковые — хеш одинаковый. Изменился хоть один байт — хеш совсем другой.
- Поэтому он отвечает только на вопрос «это один и тот же файл или нет». Узнать по нему, насколько файлы похожи, нельзя.
- Картинку для него открывать не нужно, он считается для любого файла.
- Лежит в `images.sha256`.

### Перцептивный хеш (pHash) — хеш картинки

Он же «отпечаток картинки». Описывает, как картинка выглядит, а не какие в файле байты.
Это 64 бита, записанные 16 знаками, например `8be371a6c0cce8b9`. Считает библиотека ImageHash, функция `imagehash.phash`.

Что программа делает с картинкой перед подсчётом, `analyzer/scan.py`:

```python
with Image.open(io.BytesIO(data)) as picture:
    picture.draft("RGB", (config.THUMB_SIZE * 2, config.THUMB_SIZE * 2))
    picture = ImageOps.exif_transpose(picture).convert("RGB")
    phash = str(imagehash.phash(picture))
```

| Вызов | Что делает |
|---|---|
| `Image.open` | Открывает байты файла как картинку |
| `draft` | Для JPEG: распаковать сразу уменьшенной, но не меньше 640 точек по каждой стороне. Нужно только для скорости |
| `exif_transpose` | Поворачивает картинку так, как записала камера. Без этого фото, лежащее в файле «боком», не совпало бы со своей повёрнутой копией |
| `convert("RGB")` | Приводит к обычному цветному виду: убирает прозрачность и палитру |

Что делает сама `imagehash.phash`:

1. Переводит картинку в серую.
2. Сжимает её до 32×32 точек, пропорции не сохраняются.
3. Раскладывает эти 32×32 яркости на узоры (дискретное косинусное преобразование, DCT). Получается таблица 32×32 чисел:
   в левом верхнем углу — числа про крупные формы картинки, дальше — про мелкие детали.
4. Берёт левый верхний угол 8×8, это 64 числа.
5. Находит их медиану — число, которое делит эти 64 числа пополам.
6. Каждое из 64 чисел сравнивает с медианой: больше — бит 1, иначе — бит 0.
7. Записывает 64 бита 16 знаками.

Другой размер и другое качество сжатия меняют мелкие детали, а крупные формы остаются.
Поэтому у одной картинки в разных файлах этот хеш почти одинаковый.

Лежит в `images.phash`. Если файл не открылся как картинка, там пусто, и такой файл сравнивается только по SHA-256.

### Расстояние между двумя хешами картинок

Это число бит из 64, которые не совпали (расстояние Хэмминга). Код в `analyzer/groups.py`:

```python
def distance(phash_a, phash_b):
    return (int(phash_a, 16) ^ int(phash_b, 16)).bit_count()
```

`^` оставляет единицы там, где биты разные, `bit_count` считает эти единицы.

Пример из настоящих данных — одна картинка в двух файлах:

| Файл | Размер | Перцептивный хеш |
|---|---|---|
| первый | 680×1020 | `8be371a6c0cce8b9` |
| второй | 1360×2040 | `8be371a6c0ccf899` |

SHA-256 у этих файлов разный, а хеши картинок отличаются в 2 битах из 64.

| Расстояние | Что это |
|---|---|
| 0–4 | Та же картинка |
| 5–12 | Похожий кадр, смотреть глазами |
| больше 12 | Картинки не связаны |

Верхняя граница меняется параметром `--similar`.

### Сборка групп

Каждый файл сравнивается с каждым: для 1500 файлов это больше миллиона пар.
Сравниваются только хеши, которые уже лежат в базе; сами файлы на этом шаге не читаются.
Один хеш сравнивается сразу со всеми следующими, `analyzer/groups.py`:

```python
differing_bits = np.bitwise_count(values[position] ^ values[position + 1:])
```

Сначала каждый файл — отдельная группа. Потом группы склеиваются (алгоритм «система непересекающихся множеств», union-find):

- файлы с одинаковым SHA-256 попадают в одну группу;
- файлы, у которых расстояние между хешами картинок не больше порога, попадают в одну группу.

Склейка идёт по цепочке: если А похож на Б, а Б похож на В, то все трое в одной группе,
даже когда А и В между собой отличаются больше порога.

Так делается два раза: с порогом 4 и с порогом 12. Уровень группы определяется так:

| Условие | Уровень |
|---|---|
| Группа сложилась только при пороге 12, при пороге 4 такой же группы нет | 3 — похожие кадры |
| Группа есть при пороге 4, и у всех её файлов один SHA-256 | 1 — одинаковые файлы |
| Группа есть при пороге 4, а SHA-256 у файлов разный | 2 — та же картинка, файлы разные |

Группы лежат в `duplicate_groups`, номер группы каждого файла — в `images.group_id`.

### Как считаются четыре цифры отчёта

| Цифра | Как считается |
|---|---|
| Одинаковые файлы в разных точках | Файлы раскладываются по SHA-256. Считаются наборы из двух и более файлов, которые лежат минимум в двух точках. Перцептивный хеш здесь не участвует |
| Одинаковые файлы внутри одной точки | Те же наборы по SHA-256, но все файлы набора лежат в одной точке |
| Та же картинка, но файлы разные | Число групп уровня 2 |
| Похожие кадры | Число групп уровня 3 |

### Как считается таблица «точка × точка»

Для каждой группы считается, сколько её файлов лежит в каждой точке. Дальше:

- ячейка двух разных точек получает +1, если у группы есть файл и в одной, и в другой точке;
- ячейка на диагонали получает +1, если в этой точке у группы два файла или больше.

Группы уровней 1 и 2 идут в основное число, группы уровня 3 — в мелкое `+N`.
Считаются картинки, а не файлы: картинка, которая лежит в точке три раза, даёт на диагонали единицу.

## Что получается

**Страница отчёта** — `report\index.html`, открывается в браузере. На ней:

- четыре цифры сверху и под ними четыре списка с теми же названиями:
  - одинаковые файлы в разных точках (совпадает SHA-256, файл лежит минимум в двух точках);
  - одинаковые файлы внутри одной точки;
  - та же картинка, но файлы разные;
  - похожие кадры — проверить глазами;
- матрица «точка × точка»: сколько общих картинок у каждой пары точек, на диагонали — повторы внутри точки.

Первая цифра равна числу, которое даёт запрос по `sha256` с условием `count(DISTINCT place) > 1`.
В третьем списке показаны все файлы картинки, поэтому одинаковые файлы из первых двух списков могут встретиться там ещё раз.

В списке фото стоят рядом, под каждым — точка, имя файла и размер. Нажатие открывает исходный файл.

**База** — Postgres в Docker, контейнер `photo_analyzer_postgres`, порт 5441, логин и пароль в `.env`:

- `images` — по строке на файл: точка, путь, размер, `sha256`, `phash`, номер группы `group_id` (пусто, если дубликатов нет);
- `duplicate_groups` — по строке на группу: уровень, сколько файлов, в скольких точках.

Все файлы-дубликаты между точками, группами:

```sql
SELECT g.id AS group_no, g.level, i.place, i.name
FROM duplicate_groups g
JOIN images i ON i.group_id = g.id
WHERE g.places > 1
ORDER BY g.level, g.id, i.place;
```
